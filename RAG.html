3. Chunking

Large documents are usually too big to retrieve as one unit. RAG therefore breaks them into smaller pieces called chunks.

4. Embeddings

Each chunk is converted into a numerical representation called an embedding. This demo uses simplified vectors so that you can see the concept.

5. Query Embedding

The user's question is also converted into an embedding. This is a crucial step that is often missing from beginner explanations.

Run the simulator to see the query vector.

6. Similarity Search & Ranking

The query embedding is compared against the embeddings of the stored chunks. The chunks are then ranked according to similarity. We rank the chunks based on their relationship to the query — not the embeddings by themselves.

7. Retrieval

The highest-ranked chunks are selected and passed to the generation stage as relevant context.

8. Augmented Prompt

This is where the "augmentation" in RAG happens. The original question is combined with the retrieved context before being sent to the LLM. 

Run the simulator to generate the augmented prompt.

9. LLM Generation

The LLM receives the user's question plus the retrieved context and generates the final answer.

💡 What You Should Take Away

1. RAG doesn't train the LLM

The external documents aren't normally used to retrain the model. Instead, relevant information is retrieved and supplied to the model at inference time.

2. Embeddings are for retrieval

Embeddings transform text into numerical representations that allow systems to find semantically similar information.

3. The query also gets embedded

The user's question is converted into an embedding so it can be compared against the stored chunk embeddings.

4. Retrieval happens before generation

The system first finds useful context. Only then does the LLM generate the response using that context.

5. Augmentation means adding context

Retrieved chunks are inserted into the prompt so the LLM can use external information when generating its answer.

6. Vector databases are common

In production RAG systems, chunk embeddings are commonly stored in vector databases or vector indexes for fast similarity search.
